# 상품 이미지 화질 보존 (2026-09-08)

기존 업로드는 JPEG 데이터 URL을 32,000자로 제한하면서 반복 축소하여,
검증 사진의 선택 영역 1170px가 Chromium 314px / WebKit 232px까지 줄었다.
이는 표시 영역의 CSS 잘림과 별개인 저장 화질 저하였다.

## 변경

- 기존 선택 영역 UI는 변경하지 않는다. 최대 출력 1600px, JPEG 품질 0.92
  (용량 조절 시 최저 0.90). 1,500,000자 한도에 맞추기 위한 반복 축소는 하지 않는다.
- 한도를 넘으면 오류를 표시한다. 다른 상품 사진으로 조용히 대체하지 않는다.
- 준비된 JPEG는 공개 저장 요청 시 다시 인코딩하지 않는다.
- 40,000자를 넘는 JPEG는 기존 비공개 Google Sheets의 `상품 이미지` 시트에 저장한다.
  새 외부 저장 서비스나 권한은 사용하지 않는다.
- 이미지별 SHA-256, 전체 길이, 조각 수, 생성 시각, 최대 38개의 40,000자 조각을
  하나의 행에 저장한다. 조각 앞의 `~`는 수식으로 해석되는 것을 방지한다.
- 상품 JSON에는 `/api/public-deals?image=<sha256>` 참조만 남긴다.
  GET 응답은 길이/해시/형식을 검증한 뒤 JPEG 원바이트를 반환한다.
  성공 응답만 immutable 캐시를 사용하고, 이미지 변경 시 URL도 변경된다.
- 저장은 기존 소유권·버전·수량 검증 후 동일 게시 잠금 안에서 실행한다.
  재시도는 중복 이미지를 만들지 않는다. 기존 작은 인라인 JPEG와 HTTPS URL도 유지한다.

## 배포와 인수

1. 기존 운영 Apps Script의 환경값을 유지한 채 이미지 함수/조회 분기/게시 참조화를 반영한다.
   작은 이미지의 기존 응답은 바꾸지 않아 단계적 배포가 가능하다.
2. 새 API와 클라이언트를 함께 배포하고, 실제 저장·GET·해시 일치 여부를 검증한다.
3. 시트 백업 시 `공개 상품`뿐 아니라 `상품 이미지`도 함께 포함한다.
   참조가 있는 이미지 행을 임의로 삭제하지 않는다. 이 변경은 기존 기록을 삭제하지 않는다.
4. 큰 이미지가 게시된 뒤에는 참조 URL을 이해하지 못하는 구버전 API로 롤백하면 안 된다.
   클라이언트를 되돌릴 때도 이미지 GET/참조 지원은 유지해야 한다.

이미 저화질로 저장된 JPEG의 세부 정보는 복원할 수 없다. 해당 상품은 원본 재업로드가 필요하다.
1170×2532 검증 파일은 사용자가 제공한 화면 캡처이며, 동일 선택 영역의 결과를 비교했다.
원본 전체를 무손실 저장한다고 주장하지 않는다.

## 검증

- `node --test tests/product-images.test.js`: 실제 Apps Script 함수와 API를 연결한
  저장/재조회, 소유권 방어, 재시도, 조각 손상 검사.
- `pnpm exec playwright test tests/e2e/product-image-quality.spec.js`: 두 브라우저에서
  인코딩→API 게시→시트 모형→GET→이미지 디코딩까지 실행.
  `O2O_IMAGE_FIXTURE=/절대/사진.png`로 실제 사진 비교 가능.
- 비교는 화면에서 동일 표시 크기로 수행하며, 재조회 JPEG와 업로드 JPEG의 바이트가 같은지 확인한다.
