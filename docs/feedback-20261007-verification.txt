운영 배포 상태

검증 도구 수정
배포 안내 도구의 “소유자만 갱신 가능”과 “갱신하면 반드시 실행 계정이 바뀐다”는 단정을 바로잡았습니다. 공식 문서에서 기존 버전 배포의 소유권이 유지됨을 확인했고, 현재 프로젝트에서는 권한이 확인된 공유 계정으로 기존 배포 갱신에 성공했습니다. 매니페스트만으로 실제 실행 계정이나 갱신 권한을 확정하지 않으며, 명시적 실행 설정 검토를 요구하는 기존 안전장치는 유지합니다. 관련 10건 검사는 모두 통과했습니다. 참고: https://developers.google.com/apps-script/concepts/deployments
그룹 생성 복구 검사에서 테스트 API를 지운 뒤 새 테스트 API를 등록하는 사이에 백그라운드 요청이 실제 Vite 서버의 404로 빠졌습니다. 저장된 실패 추적에는 이전 그룹 주문의 404와 그에 따른 정상 취소 보상 후 새로운 그룹 ID의 주문이 기록됐습니다. 애플리케이션이 동일한 예약을 임의로 복제한 것으로 단정할 근거가 아니며, 변경 전 해당 검사를 독립 반복한 4건은 통과했습니다.
새로 등록한 Playwright 경로의 우선순위를 사용해 기존 테스트 응답을 유지한 채 응답 경로를 교체하도록 고쳤습니다. 응답 교체에 빈 구간을 만들지 않습니다.
별도 검사 실행이 먼저 실행한 검사의 개발 서버를 재사용하면, 앞 검사가 끝나며 서버가 꺼져 뒤 검사에 연결 거절이 발생했습니다. O2O_E2E_PORT 및 O2O_E2E_REUSE_SERVER 설정으로 각 실행의 서버를 명시적으로 분리할 수 있도록 고쳤습니다. 원래의 개발 기본값은 유지합니다.
복합 기능 검사에서는 전체 검사 제한을 120초로 지정하고, 개별 화면 확인 10초 및 계약상 5초 갱신 검증은 유지했습니다. 전체 제한과 기능의 응답 시간 기준을 동일한 것으로 취급하지 않습니다.

실제 운영 확인
기존 비공개 검증용 텍스트 그룹의 호스트 권한으로 서로 독립된 요청을 보내 저장·재조회·같은 변경 ID의 중복 방지와 입금확인요청·취소를 확인했습니다. 고객 상품이나 고객 입금 상태를 변경한 검사가 아닙니다. 이 그룹에는 실제 주문에 연결된 두 번째 참여자가 없어 고객 두 기기 검수 완료로 확대 해석하지 않습니다. 미등록 참여자의 잘못된 키는 정상적으로 403 invalid_capability로 거절됐습니다.
