## 관리자 화면에서 PIN 변경 — 2026-09-09

- 사용자 확인을 받아 이번 PIN 변경 기능은 계약 범위 제한의 예외로 구현했다. 계약 가드 문서는 변경하지 않았다.
- 경로: 관리자 앱 → 상품·주문 관리자 운영 관리 → 기존 PIN으로 관리자 확인 → 관리자 PIN 변경. 현재 PIN, 숫자 8~12자리 새 PIN, 새 PIN 확인을 입력한다.
- 서버가 현재 PIN을 검증하고 scrypt(N=16384, r=8, p=1)·임의 16바이트 salt·64바이트 해시만 중앙 ScriptProperties에 저장한다. API 응답, 분석 이벤트, 브라우저 저장소에는 PIN/해시를 기록하지 않는다.
- 첫 변경 전 명시적인 빈 중앙 저장소만 기존 서버 환경변수 PIN을 사용한다. 첫 변경 뒤에는 중앙 해시가 우선하며, 저장소 장애·손상·구버전 collector 응답에서 기존 PIN으로 우회하지 않는다.
- 동시에 다른 PIN으로 변경하면 버전 충돌로 차단한다. 동일 변경의 중복 요청 및 저장 후 응답 유실은 수행자·요청 ID·새 PIN을 확인하여 중복 변경 없이 복구한다.
- 관리자 상품·주문 API, 그룹 관리자 API, 그룹 주문/입금 관리 API가 같은 중앙 검증을 사용한다. GAS는 관리자 assertion의 인증 버전도 확인하여 PIN 변경 후 구버전 Vercel 배포가 환경변수 PIN으로 접근하는 경로를 차단한다.
- 이미 발급된 그룹 관리자 capability 세션은 유지한다. 전체 세션 로그아웃 기능은 추가하지 않았다. 중앙 credential 속성을 삭제하거나 GAS 15 이하로 되돌리면 초기 PIN 경로가 다시 열릴 수 있으므로 운영 복구 시 기존 속성과 16 이상 저장 코드를 보존해야 한다.
- 운영 PIN 자체는 이번 기능 배포에서 바꾸지 않았다. 관리자 본인이 새 PIN을 입력하여 변경한다. 상품·주문·입금 데이터도 변경하지 않았다.

## 오전 재검수 피드백 — 2026-09-09

이번 요청은 기존 기능의 재현 가능한 오류 수정과 앞서 명시적으로 승인한 관리자 기능의 진입 동선 보완으로 처리했다. 정식 계정 인증·다른 기기 소유권 자동 복구를 새로 추가한 것은 아니다.

### 확인한 원인과 수정

1. 관리자 앱 진입: 사용자 상세/채팅 화면 상태가 남아 관리 목록을 가렸다. 관리자 진입 시 전용 관리 화면을 우선하고 역할 전환 시 이전 화면 상태를 초기화했다. 상품 선택 후 이미지 변경·비공개 삭제·참여 취소로 연결하며, 상세/채팅에서 관리 목록으로 돌아오는 동선을 유지한다. PIN 변경은 인증 후 펼침 영역에서 제공한다.
2. 사장님 이력: 권한 확인된 상품의 중앙 주문 스냅샷에 과거 주문 이벤트를 병합하도록 조회를 보완했다. 조회 실패 시 마지막 정상 목록을 유지하고 재시도를 제공한다. 관리 키가 없는 브라우저와 실제 빈 목록을 구별한다. 전화번호 입력만으로 다른 사람의 관리 권한을 복구하지 않는다.
3. 첫 상품 수정: 중앙 상품의 `publishVersion`보다 로컬 `updatedAt`을 우선하면서 낡은 수정 버전을 보내던 경로를 재현했다. 상품 버전과 그룹 상태 버전을 따로 비교하여 최신 내용을 사용한다. 편집을 시작한 이후의 실제 경쟁 수정은 계속 충돌로 차단하고 입력을 보존한다.
4. 사용자 생성 그룹의 입금/내 주문 불일치: 생성자 주문이 중앙에 저장되기 전에 입금 요청이 먼저 적용되면 이후 주문 저장이 거절될 수 있었다. 입금 요청 전 중앙 주문 저장을 확인하고, 미저장 주문만 기존 예약·주문 ID로 재전송한다. 저장을 확인할 수 없으면 입금 상태를 변경하지 않는다. 조회 성공이 작업 실패 안내를 즉시 지우던 UI 오류도 분리했다.
5. 첫 수량·목표 인원 변경: 오래 걸린 조회가 변경 완료 후 낡은 그룹 캐시를 다시 채우는 순서 문제를 실제 GAS 코드로 재현했다. 변경마다 캐시 세대를 바꿔 이전 조회가 새 캐시를 덮지 못하게 했다. 세대 키가 없거나 캐시가 실패하면 중앙 데이터를 직접 읽는다. 조회 이후 다른 사람이 실제로 수정한 경우의 버전 충돌 보호는 유지한다. 제보자의 물리적 기기에서 같은 원인이었는지는 직접 확인하지 않았다.
