## 이번 수정 내용

1. **입금 전 주문 확인 비용 감소**: 예약 연결과 중앙 저장 확인값이 일치하는 로컬 주문은 전체 주문 이력을 다시 읽지 않는다. 추가 확인이 필요한 경우 `groupId`를 지정해 해당 그룹의 주문만 투영한다. 소유권과 주문 ID 충돌·최신 버전 확인은 그룹 필터보다 먼저 적용한다. 로컬 저장 확인값은 권한 증명이 아니며 실제 입금 변경은 서버에서 다시 검증한다.
2. **미완료 주문과 오래된 로컬 기록 구분**: 진행 중인 추가 주문·예약이 있으면 입금을 막는다. 정상 중앙 주문이 존재할 때 예약 증명 없는 과거 로컬 표시용 주문을 그 주문의 입금 선행 조건으로 재게시하지 않는다. 해당 로컬 기록을 삭제하거나 중앙 기록으로 임의 채택하지 않는다.
3. **서버 정합성 검증**: 입금 변경에 사용할 검증된 중앙 주문 수량 합계와 참여자의 선택 수량이 일치하는지 확인한다. 실제 추가 예약의 주문 저장이 미완료이면 일부 주문만 입금 처리하지 않는다. 누락·상충하는 예약 증명이나 주문 연결은 계속 거절한다.
4. **변경 이력 읽기 비용 감소**: 그룹 변경 전에 과거 이력을 한 행씩 원격 조회하던 부분을 최대 100행 단위로 읽는다. 완료된 이력 250건의 재현에서 잠금 중 시트 읽기가 268회에서 25회 이하로 줄었다. 다른 그룹의 이력은 실행하지 않고, 서로 다른 변경 요청 사이에 오래된 조회값을 재사용하지 않는다. 실제 변경 작업의 권한·버전·예약 검증과 잠금은 유지한다.
5. **버튼 주변 처리 결과 표시**: 입금 버튼을 누르면 해당 참여자 행에서 주문 확인·입금 저장 진행 상태를 표시하고 처리 중 중복 입력을 막는다. 성공·오류·결과 재확인을 버튼 가까이 표시한다. 응답 유실 후 다시 확인할 때 같은 변경 요청을 사용해 다음 입금 단계로 잘못 진행하지 않도록 검수했다.
6. **알 수 없는 수집 동작 거절**: GAS `doPost`에 알 수 없는 `action`이 들어오면 `invalid_action`으로 거절하여 분석 이벤트 저장으로 흘러가지 않게 했다.
7. **서버 상태 확인 응답의 성공 오인 방지**: 업무 POST가 collector GET 상태 확인 응답을 받으면 공통 API 경계에서 `502 upstream_invalid_response`로 거절한다. 기존 목록과 보류 중 요청을 유지하고 기존의 동일 요청 재시도만 사용한다. 실제 저장됐을 가능성이 있으므로 화면에서도 처리 실패를 단정하지 않고 결과 확인이 필요함을 안내한다.

## 추가 검수와 한계

`tests/helpers/payment-pipeline.js`는 실제 Vercel API handler → 로컬 HTTP 수집기 → 현재 `apps-script/Code.gs`의 `doPost` → 시트 저장 경로를 연결한다. Google의 Spreadsheet·Lock·Cache·Properties·Content 서비스만 격리 대역으로 제공하며, 입금 상태를 테스트 코드의 전이 표로 직접 바꾸지 않는다.

`tests/e2e/payment-pipeline.spec.js`에서 다음을 검수했다.

| 시나리오 | 확인한 결과 |
|---|---|
| 호스트 본인 요청 → 요청 취소 → 재요청 → 호스트 확인 | 중앙 주문·참여자 상태·버전·이력이 함께 변경되고 내 주문 및 새로고침 후 재입장에도 유지됨 |
| 전체 주문 이력 504, 늦게 도착한 이전 조회 응답 | 저장 확인된 호스트 주문의 입금을 전체 이력 조회가 막지 않고 늦은 이전 상태가 최신 입금을 되돌리지 않음 |

| 로컬 저장 확인값은 있지만 중앙 주문 연결이 없음 | GAS가 거절하고 참여자 입금 상태·버전·이력을 변경하지 않음 |

추가 예약 수량의 저장 누락·상충, 권한 증명, 과거 연결 복구 제한, 알 수 없는 `action`의 무기록 거절 등은 단위·API·GAS 코드 테스트로 함께 확인했다.

**이 결과는 실제 API·GAS 코드를 실행한 가상 시트 검수이다. 실제 Google 실행환경·네트워크 성능이나 고객의 실제 휴대폰 검수 결과가 아니다.** 모바일 Chromium/WebKit은 브라우저 에뮬레이션이다. 실제 운영 상품을 주문하거나 입금 상태를 바꾸는 검수는 수행하지 않았다.
