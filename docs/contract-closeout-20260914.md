## 주요 변경내역

- 그룹 채팅, 5초 갱신, 최신 100건, 재접속 기록, 관리자 잠금과 미확인 배지를 구현·회귀검증했다.
- 그룹 4단계 상태, 참여자 입금 상태, 한 단계 복구, 중앙 변경 이력, 목표 인원 규칙, 예상금액 계산기, 11개 카테고리를 일관되게 연결했다.
- 공유 URL·모바일 공유 시트·프로필 확인 뒤 딥링크와 합의된 행동 이벤트를 반영했다.
- 중앙 요청의 지연·응답 유실·중복 클릭·재시도에서 같은 작업이 중복 반영되지 않도록 보완했다.
- 중앙 주문을 먼저 조회한 뒤 아직 전송되지 않은 주문만 게시하도록 바꿨다. 다른 화면에서 이미 입금완료된 주문의 오래된 로컬 사본을 다시 전송해 충돌·시간초과를 만들던 경로를 차단했다.
- 전화번호 표시 형식 차이로 같은 주문을 다른 주문처럼 판단하던 문제와, 늦게 끝난 과거 요청이 최신 입금 상태를 삭제·복구하는 경쟁 조건을 수정했다.
- 내 주문은 중앙의 최신 입금 상태를 유지하며, 읽기 새로고침마다 전체 이력을 중복 조회하지 않도록 요청량을 줄였다.
- 그룹 채팅은 응답 완료 후 5초를 더 기다리는 방식에서 요청 시작 간격 약 5초로 바꿨고, 새 메시지 배지는 5초마다 그룹별 읽기를 병렬 처리한다.
- 중앙 주문과 완료 예약이 정확히 일치하는 기존 고객 그룹만 안전하게 다시 연결하도록 복구 경로를 추가했다. 근거가 없거나 모순되는 데이터는 임의 생성하지 않고 점검 안내를 유지한다.

### 2026-09-16 ~ 09-19 추가 수정

- `주문 이력 다시 불러오기`가 배경 동기화와 겹치면 아무 요청도 만들지 않고 무시되던 문제를 고쳤다. 누르면 즉시 진행 표시로 바뀌고 새 조회에 도달하며, 연속 클릭의 중복 조회 방지는 유지한다.
- 다른 보류 요청 때문에 잠긴 입금 버튼이 무엇을 먼저 확인해야 하는지 해당 참여자 줄에 안내한다. 중복 반영을 막는 잠금 자체는 유지한다.
- 내 주문 중앙 조회가 시간 초과로 실패하던 원인을 제거했다. 전화번호 뒤 4자리로 전체 이벤트 시트를 훑던 방식을, 권한 확인된 사장님·관리자 조회가 이미 쓰던 주문 스냅샷 정확 일치 방식으로 바꿨다. 전체 컬럼 검색은 한 번뿐이고 과거 스냅샷을 건너뛰지 않는다. 이 변경은 Apps Script v25로 반영됐다.
- 이벤트 로그에서 복원하는 과거 주문 집합을 전화번호와 이벤트 시트 행 수를 키로 캐시한다. 현재 주문과 참여자 기반 입금 상태 투영은 매 요청 새로 읽으므로 캐시가 입금 상태를 고정하지 않는다.
- 내 주문 화면이 게시 대기열에 묶여 멈추던 문제를 고쳤다. 화면 상태를 권한 있는 읽기 직후에 확정하고, 한 주기의 게시 건수를 제한하며, 게시 요청에 제한 시간을 뒀다. 중단된 게시는 그 자리 재시도나 최종 거절이 아니라 기존 중앙 재확인 경로로 넘어간다.
- 관리자 인증 저장소 요청의 제한 시간을 늘렸다. 결과가 불확실한 인증 응답의 자동 재시도는 추가하지 않았다. 중앙 제한 슬롯을 소모해 잠금을 앞당길 수 있기 때문이다.
