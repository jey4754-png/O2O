## 원인 확인

보관된 운영 로그 `.vercel/feedback-20260915/`에서 `/api/customer-orders`의 `action: "list"` 요청이 `upstream_timeout`(504)으로 종료된 기록을 확인했다. 이 읽기가 실패하면 내 주문 화면은 모든 주문 카드를 `입금 상태 확인 필요`로 표시한다. 마지막으로 확인된 상태를 임의로 최신 상태처럼 보여주지 않기 위한 기존 설계이며 이 동작 자체는 유지한다.

문제는 그 다음이었다. `주문 이력 다시 불러오기`는 30초 주기의 배경 동기화가 실행 중이면 눌러도 아무 요청도 만들지 않고 조용히 무시됐다. 화면 문구도 그대로여서 버튼이 죽은 것처럼 보였다. 1번 증상과, 새로고침(페이지 재적재) 뒤에는 정상 반영됐다는 8번 관찰이 모두 이 경로로 설명된다.

- **주문 이력 다시 불러오기(1·5·8번 관련).** 버튼을 누르면 즉시 진행 표시로 바뀌고, 배경 동기화가 실행 중이더라도 그 뒤에 새 조회를 반드시 한 번 실행한다. 같은 버튼을 연속으로 눌렀을 때 중앙 이력 조회가 중복 실행되지 않는 기존 보호는 그대로 유지한다.

- **잠긴 입금 버튼 안내(2·3번 관련).** 같은 사용자의 다른 상태 변경 요청 결과가 확인되지 않은 동안에는 입금 버튼이 잠긴다. 이 잠금 자체는 중복 반영을 막는 기존 보호라 유지하고, 대신 어떤 요청을 먼저 확인해야 하는지와 어느 버튼을 눌러야 하는지를 해당 줄에 표시하도록 했다.
