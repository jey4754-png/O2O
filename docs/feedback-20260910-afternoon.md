# 2026-09-10 오후 재검수 피드백

## 범위와 현재 상태

첨부한 카카오톡 화면은 오류 증상과 참고 자료로 사용했다. 사용자의 요청은 해당 피드백 반영 및 전달용 카카오톡 문안 작성이다. 메시지는 발송하지 않았다.

계약의 그룹 채팅, 입금 상태·이력, 데이터 연속성, 권한 검증 및 모바일 오류 수정과 앞서 승인된 관리자 PIN·상품 삭제·참여 취소·이미지 교체 기능의 회귀 수정으로 분류했다. 신규 취소 흐름이나 계정 기반 권한 복구는 추가하지 않았다. 중앙 기록이 없는 과거 상품·그룹을 추정하여 생성하지 않았다.

공통 코드 수정은 운영에 배포했다. **양파의 누락된 그룹 연결과 맥주 60캔 2건의 중앙 기록 부재는 미해결이며, 등록 당시 브라우저의 기록 확인이 필요하다.**

## 확인한 원인과 반영 내용

1. **반복 저장과 서버 혼잡**: 같은 주문도 객체 속성 순서 차이 때문에 변경으로 판단되어 다시 저장될 수 있었다. 서버가 수용하는 필드만 정규화하여 비교하고, 실제 수량·입금 상태 변경은 계속 저장하도록 했다. 상품 게시 응답에서 생략되는 로컬 생성자 필드는 제출본과 병합해 보관하며, 확정된 서버 변경과 게시 확인값이 일치하도록 했다. 다른 탭의 실제 편집과 미저장 편집은 유지한다.
2. **이력 조회 비용**: 한 번의 주문 목록 응답에서 같은 예약 이력 시트를 반복해서 읽던 경로를 한 번의 조회로 공유했다. 기존 이벤트의 필요한 행은 최대 100행 단위로 묶어 읽되, 소유권 필터와 정확한 일치 조건을 유지한다. 변경 작업이나 서로 다른 요청 간에는 해당 스냅샷을 공유하지 않는다.
3. **관리자 PIN 진입 지연**: 시도 제한 확인 응답에 인증 저장소 스냅샷을 함께 받아 불필요한 상위 저장소 호출 한 번을 줄였다. 인증된 목록·주문 조회의 제한된 일시 오류만 한 번 재시도한다. 잘못된 PIN, 시도 제한, 인증 저장소 장애 및 변경 작업은 자동 재시도하지 않는다.
4. **0건 표시 후 복귀**: 관리자 주문 목록에서 로딩·조회 실패·실제 빈 결과를 구별하고, 같은 상품 재조회 중에는 마지막 정상 목록을 유지한다. 조회 중이거나 오류 상태이면 참여 취소를 막는다.
5. **이미지와 삭제 후 화면 갱신**: 이미지 주소가 바뀌면 실패 대체 표시를 다시 평가하고, 관리자 저장 성공 결과를 공개 상품 캐시에 즉시 반영한다. 늦게 도착한 이전 조회가 삭제된 상품이나 이전 이미지로 되돌리지 않도록 했다. 중앙 목록에 없다는 이유만으로 로컬 상품을 삭제하지 않는다.
6. **입금과 내 주문 연결**: 검증된 예약·주문 연결을 기준으로 입금 변경 전 주문 투영을 확인하고, 복구가 확인된 저장에는 오래된 조회 전용 오류 표시가 남지 않게 했다. 그룹·예약 증명이 없는 과거 건을 임의 연결하는 경로는 추가하지 않았다.

운영에서 11:06~11:37 KST 사이 조회한 최근 5xx 로그 100건에는 `collector_busy`와 `upstream_timeout`이 포함됐다. 반복 저장과 조회 비용 증가는 혼잡을 만들 수 있는 코드 원인으로 재현했다. 이 로그만으로 고객이 경험한 모든 오류의 원인이 동일하다고 단정하지 않는다.
